#  项目设计文档：极客风互动动态壁纸 (CLI-Wallpaper)

## 1. 项目概述
本项目旨在开发一款轻量级、支持命令行交互的 Windows 动态壁纸程序。程序将驻留在桌面底层，提供系统状态监控（CPU/内存/时间）、番茄钟休息提醒以及情绪陪伴功能。核心设计原则为**“极致的资源调度与零打扰”**，确保在图书馆等场景下不影响主机的续航与散热。

## 2. 核心技术栈选型 (Tech Stack)

为了兼顾底层 API 调用与前端终端 UI 的渲染，推荐以下两套技术栈方案：

*   **方案 A：C# WPF + WebView2（推荐，性能最优，最适合 ThinkBook 续航）**
    *   **语言/框架**：C# (.NET 8) + WPF
    *   **渲染引擎**：Microsoft.Web.WebView2（用于加载前端伪终端 UI）
    *   **优势**：调用 Windows API 最方便，内存占用极低，编译后无需复杂依赖。
*   **方案 B：Electron + Vue3 + xterm.js（前端生态好，开发快）**
    *   **语言/框架**：Node.js + Electron
    *   **渲染引擎**：Chromium
    *   **优势**：可以使用 `xterm.js` 轻松实现完美的命令行终端效果，跨平台。
    *   **劣势**：内存占用较高，后台常驻可能影响笔记本续航。

## 3. 系统架构设计 (System Architecture)

采用 **CLI + 守护进程 (Daemon)** 分离的微服务架构思路：

```text
┌─────────────────────────────────────────┐
│         用户交互层 (伪终端 UI)          │
│  [CLI 界面] 输入指令 / 输出状态 / 动画  │
└──────────────────┬──────────────────────┘
                   │ 进程间通信 (IPC / 命名管道)
                   ▼
┌─────────────────────────────────────────┐
│           后台核心守护进程              │
│  ├─ 窗口层级管理器 (WorkerW 劫持)       │
│  ├─ 硬件状态轮询器 (WMI / 性能计数器)   │
│  ├─ 状态机与定时器 (番茄钟 / 情绪逻辑)  │
│  └─ 智能挂起控制器 (电源/全屏/遮挡检测) │
└─────────────────────────────────────────┘
```

## 4. 核心模块实现原理

### 4.1 窗口层级劫持（实现“壁纸化”）
Windows 桌面由 `Progman` (Program Manager) 和 `WorkerW` 组成。
*   **实现逻辑**：通过调用 `user32.dll`，向 `Progman` 发送未公开的消息 `0x052C`，强制系统在图标层下方生成 `WorkerW` 窗口。
*   **窗口嵌入**：获取 `WorkerW` 的窗口句柄 (HWND)，将我们的渲染窗口作为其子窗口强行塞入，实现“夹在壁纸和图标之间”的视觉效果，并设置鼠标点击穿透（`WS_EX_TRANSPARENT`）。

### 4.2 硬件状态获取 (核数/温度/时间)
*   **实现逻辑**：通过 WMI (Windows Management Instrumentation) 查询硬件信息。
*   **核心代码示例 (C#)**：
    ```csharp
    // 获取 CPU 核心数与当前负载
    using (var searcher = new ManagementObjectSearcher("SELECT NumberOfCores, LoadPercentage FROM Win32_Processor"))
    {
        foreach (var obj in searcher.Get())
        {
            int cores = Convert.ToInt32(obj["NumberOfCores"]);
            int load = Convert.ToInt32(obj["LoadPercentage"]);
            // 推送到前端 UI 显示
        }
    }
    ```

### 4.3 伪终端 (CLI) 交互解析
*   **实现逻辑**：前端使用 HTML5 Canvas 或 `xterm.js` 模拟终端。后端维护一个指令解析器（Parser）。
*   **交互流**：用户输入 `help` 或 `rest` -> 前端捕获 `keydown` -> 通过 IPC 发送给后端 -> 后端状态机匹配指令 -> 返回预设文本/执行动作 -> 前端打印输出。

### 4.4 状态机与情绪陪伴
*   **实现逻辑**：基于时间戳的有限状态机 (FSM)。
*   **规则引擎**：
    *   `Idle > 30min` -> 触发“摸鱼”状态，输出调侃文本。
    *   `Active > 45min` -> 触发“疲劳”状态，强制弹出休息提醒（类似番茄钟）。
    *   输入 `mood sad` -> 触发情绪陪伴模块，输出治愈系文本或播放白噪音。

## 5. ️ 关键机制：智能挂起与电池保护 (Power & Thermal Management)

考虑到设备日常需要携带去图书馆，且对电池保养和散热有极高要求，本程序必须实现严格的资源调度：

1.  **电源状态监听**：
    *   通过系统 API 监听 `PowerModeChanged` 事件。
    *   **策略**：一旦检测到系统从“接通电源”切换为“使用电池”，立即将壁纸渲染帧率从 60fps 降至 1fps，甚至直接暂停渲染循环，仅保留后台定时器，将 GPU 占用率降至 0%。
2.  **前台遮挡与全屏检测**：
    *   通过 `GetForegroundWindow` 定时检测当前焦点窗口。
    *   **策略**：如果检测到有全屏应用（如打游戏、看视频）或壁纸窗口被完全遮挡，立即挂起硬件轮询线程和渲染线程，避免抢占 CPU 时间片导致风扇狂转。
3.  **温度联动（进阶）**：
    *   读取主板温度传感器（如通过 LibreHardwareMonitor 库）。
    *   **策略**：当 CPU 温度超过阈值（如 75℃，考虑到日常有自行处理硅脂等硬件维护，对温度阈值有清晰认知），自动暂停壁纸的所有动画效果，仅保留静态文本，辅助散热。
